## Decision Receipt M2.1 — Shared cart and checkout pricing (#97)

Thomas Chen selected this improvement for [#97](https://github.com/gwan-kib/COSC-310-Lab-Food4Thought/issues/97). The [Canvas lab assignment](https://canvas.ubc.ca/courses/196634/assignments/2615087) identifies the receipt as M2.1. The issue calls it M2.3.

After [#113](https://github.com/gwan-kib/COSC-310-Lab-Food4Thought/pull/113) and [#115](https://github.com/gwan-kib/COSC-310-Lab-Food4Thought/pull/115) merged, the [cart service](https://github.com/gwan-kib/COSC-310-Lab-Food4Thought/blob/95c7c8ed289d15f4b05de098bae5608f7c6c52f3/app/services/cart.py#L141-L155) imported cent conversions from the order schema. It repeated the line and subtotal formulas used in [checkout](https://github.com/gwan-kib/COSC-310-Lab-Food4Thought/blob/95c7c8ed289d15f4b05de098bae5608f7c6c52f3/app/services/checkout.py#L132-L158), and each subsystem declared its own two-decimal amount type.

Keeping the formulas in each service makes each calculation easy to find, but a pricing change requires synchronized edits. Sharing the entire pricing workflow would couple how a cart displays an unavailable item with checkout's decision to reject it. The [shared pricing module](../../app/core/pricing.py) therefore defines only the canonical amount and exact arithmetic. Cart views, new purchases and order validation use it. Each service selects its own inputs, and a replay returns the saved snapshot.

The [multi-subsystem test](../../tests/test_cart_api.py) `test_cart_and_checkout_reprice_but_retry_keeps_the_saved_order` uses an authenticated cart API client, real checkout service, and isolated catalog, account, cart and order stores. Two soups and one bread total 23.25. Raising the soup price from 10.00 to 11.50 produces 26.25 in the refreshed cart and purchased order. After a second price change, a fresh checkout service returns the original saved order for the original cart revision. The same 73 focused tests passed before and after extraction.

[Gwantana’s review of PR #121](https://github.com/gwan-kib/COSC-310-Lab-Food4Thought/pull/121#pullrequestreview-6002501869) identified a provenance ID collision and a responsibility-map edit that applied #97’s receipt label to other owners. The revision preserves the disclosures from main, assigns #97 entry 72, and scopes M2.1 to #97 in the map. The pricing test now performs menu edits through the assigned restaurant manager’s authenticated PATCH route. The [provenance record](../PROVENANCE.md#entry-72-share-exact-pricing-across-cart-views-and-checkout-97) records the revision. Re-review and merge are pending.

## Team Receipt M2.3 evidence for issue #96

**Owner and source.** Sreeram Nara is the assignee for [issue #96](https://github.com/gwan-kib/COSC-310-Lab-Food4Thought/issues/96) under M2 §5. The weakness was exposed by his account and cart work (#79–#86, #90, #107).

**Observed weakness.** Before the change, customers and sessions already read and saved through the [shared helper](https://github.com/gwan-kib/COSC-310-Lab-Food4Thought/blob/95c7c8ed289d15f4b05de098bae5608f7c6c52f3/app/core/json_file.py#L13-L23), and staff used its reader. But there were **four** separate atomic-save implementations, in the shared helper, the [cart repository](https://github.com/gwan-kib/COSC-310-Lab-Food4Thought/blob/95c7c8ed289d15f4b05de098bae5608f7c6c52f3/app/repositories/cart.py#L131-L145), the [order repository](https://github.com/gwan-kib/COSC-310-Lab-Food4Thought/blob/95c7c8ed289d15f4b05de098bae5608f7c6c52f3/app/repositories/order.py#L76-L84) and the [restaurant repository](https://github.com/gwan-kib/COSC-310-Lab-Food4Thought/blob/95c7c8ed289d15f4b05de098bae5608f7c6c52f3/app/repositories/restaurant.py#L95-L116). The cart and order repositories also each defined their own `_exact_int` reader ([cart](https://github.com/gwan-kib/COSC-310-Lab-Food4Thought/blob/95c7c8ed289d15f4b05de098bae5608f7c6c52f3/app/repositories/cart.py#L29-L45), [order](https://github.com/gwan-kib/COSC-310-Lab-Food4Thought/blob/95c7c8ed289d15f4b05de098bae5608f7c6c52f3/app/repositories/order.py#L26-L40)), while the shared helper still parsed with plain `json.loads`. The duplication caused repeated defects in review. [Thomas's PR #113 review](https://github.com/gwan-kib/COSC-310-Lab-Food4Thought/pull/113#pullrequestreview-5985679407) found that the cart's save left a temporary file after a serialization failure and that quantities past Python's 4300-digit integer-text limit could not be saved or reloaded. Both were fixed in the cart repository only, and his [next review](https://github.com/gwan-kib/COSC-310-Lab-Food4Thought/pull/113#pullrequestreview-5986926488) found the same integer bug in the order repository. The shared helper still had it: a 5,001-digit integer round trip failed before #96.

**Alternatives and decision.**
- Keeping a copy per repository needs no migration, but every new store (such as staff accounts in #107) would need the same fixes again.
- A generic base `JsonRepository` class would centralize more, but it would change every owner's repository, and the repositories differ in locking, validation and error types.
- The selected [shared helper](../../app/core/json_file.py) owns only reading and atomic replacement: exact integers of any length, strict UTF-8, the store's own error for missing, corrupt or wrongly encoded files, and temporary-file cleanup on any failed save (reported if even that deletion fails). Each repository keeps its own validation and locks. The cart repository now reads and saves through it, and the order reader uses its exact parser. The restaurant repository and the order write path can adopt it later without a format change.

**Result and trade-off.** The read-and-replace guarantees live in one tested module. Customer, session, staff and cart stores get them automatically. For #107, the staff repository added its provisioning writes and delegated atomic file replacement to the existing `write_json_array` helper. The merged change removed 59 lines and added 46 in `app/` (`git diff --numstat 67417bb^1 67417bb -- app`, including the review fixes), and no API, schema or file format changed. Of the four atomic-save implementations, the cart's was removed; the order write path and the restaurant repository keep theirs. That remaining duplication is a known trade-off, left to those repositories' maintainers.

**Verification and review.** The same 120 characterization cases across the cart, customer, order and checkout-integration suites passed before and after the refactor, with their behavioural assertions unchanged. The only test edits moved three monkeypatch targets in `tests/test_cart_repository.py` and `tests/test_cart_service.py` (from `app.repositories.cart` to `app.core.json_file`), because the I/O they break moved into the helper. [`tests/test_json_file.py`](../../tests/test_json_file.py) adds the helper's own tests, including the 5,001-digit round trip that failed before the change. [Gwantana's review of PR #116](https://github.com/gwan-kib/COSC-310-Lab-Food4Thought/pull/116#pullrequestreview-6002361858) found that byte input auto-detected UTF-16/32, and that a failed cleanup could replace the store's error. Both got failing regressions first, then fixes, and her [re-review](https://github.com/gwan-kib/COSC-310-Lab-Food4Thought/pull/116#pullrequestreview-6002473659) confirmed them. PR #116 was [approved](https://github.com/gwan-kib/COSC-310-Lab-Food4Thought/pull/116#pullrequestreview-6002488687) and merged on 2026-11-21 with green CI. The [provenance record](../PROVENANCE.md#entry-68-shared-json-array-store-helper-architectural-improvement) records the AI contribution; Sreeram reported on 2026-11-20 that he has read the code and can explain it.

## Team Receipt M2.3 evidence for issue #98

**Owner and source.** Gwantana Kiboigo is the assignee for [issue #98](https://github.com/gwan-kib/COSC-310-Lab-Food4Thought/issues/98) under M2 §5. The evidence uses M1's working frontend as the starting point for M2 integration.

**Observed weakness.** Discovery's [`getJson`](https://github.com/gwan-kib/COSC-310-Lab-Food4Thought/blob/f142e6ba41aa0fe74e3a3586113835eb41d0aaf6/frontend/app.js#L13-L33), [Create restaurant's submission handler](https://github.com/gwan-kib/COSC-310-Lab-Food4Thought/blob/f142e6ba41aa0fe74e3a3586113835eb41d0aaf6/frontend/create-restaurant.js#L74-L99), and Edit restaurant's [`fetchWithTimeout`](https://github.com/gwan-kib/COSC-310-Lab-Food4Thought/blob/f142e6ba41aa0fe74e3a3586113835eb41d0aaf6/frontend/edit-restaurant.js#L64-L85) each negotiate JSON and decode response bodies. Create and Edit also maintain separate 15-second abort timers. An additional M2 screen following these examples would have to choose or copy one of three implementations, making request changes and failure handling easier to miss across screens.

**Alternatives and decision.** Keeping the helpers per page minimizes migration work and leaves three transport implementations to maintain. A client that also owns endpoint methods, response validation, and user-facing errors could give screens a uniform interface, but would couple discovery, forms, and future workflows whose error and retry rules differ. The selected [shared ES module](../../frontend/api-client.js) handles headers, JSON encoding and decoding, and an optional deadline in one place. It exposes `ok`, `status`, and `body` so each page can interpret the result. The existing static server loads it through standard browser modules without a build step.

**Result and trade-off.** One implementation now serves all three pages. Discovery still handles stale selections and independent menu errors. The forms still interpret 422 field errors and confirm writes against the expected status and payload. Create and Edit still use a 15-second deadline through body reading, and an uncertain write requires user verification before retry. Discovery retains its existing untimed reads. Endpoint paths, payload schemas, backend rules and storage are unaffected. Keeping page-specific decisions local leaves some repeated error formatting and validation rendering, which are outside this transport change.

**Review follow-up.** Thomas Chen identified that the transport needed to accept `Authorization` for reuse by protected M2 screens. The caller can now supply headers, and the client fills in missing JSON headers. This keeps token ownership with the caller and supports the [agreed bearer transport](../AUTH_DESIGN.md#agreed-policy-decisions). [Thomas's review](https://github.com/gwan-kib/COSC-310-Lab-Food4Thought/pull/112#pullrequestreview-5985511805) also identified the provenance conflict resolved when integrating `main`.

After integrating `main`, `python -m pytest -q` passed all 466 tests with Chromium required.
